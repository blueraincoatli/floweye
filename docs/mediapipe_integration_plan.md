# 规划：集成 Google ML Kit Face Mesh 实现基于关键区域的注视方向检测

## 1. 目标

利用 **Google ML Kit Face Mesh Detection** 技术，在 Flutter 应用中实现判断用户是否大致看向本设备屏幕方向的核心功能。该方案需重点利用人脸 **3D 面部网格 (Face Mesh) 中的特征点子集**（眼部、眉毛、额头、颧骨区域）和**（如果可用）精确的头部姿态信息**，以提高对部分面部遮挡（如氧气面罩）的鲁棒性。

**当前策略：优先实现 Android 版本，接受 iOS 平台暂不支持的限制。**

## 2. 核心技术与依赖

*   **核心技术:** Google ML Kit Face Mesh Detection (基于 MediaPipe 技术)
*   **Flutter 插件:** `google_mlkit_face_mesh_detection` (由 flutter-ml.dev 发布)
    *   **注意:** 此插件目前 (截至 2024 年 Q3) 仍处于 Beta 阶段，且**仅支持 Android 平台**。iOS 平台的支持需要等待 Google 或插件开发者更新。
*   **关键数据依赖:**
    *   **3D 面部网格特征点:** 从插件输出的 **468 个 3D 点** 中，重点提取和使用以下区域的点（具体索引需参考插件 API 或 MediaPipe 文档）：
        *   虹膜区域 (Iris region): 需要确认插件是否直接提供虹膜点，或提供足够精细的眼部轮廓点用于估算。
        *   眼睑 (Eyelids): 上下轮廓点。
        *   眼角 (Eye Corners): 内外眼角点。
        *   眉毛 (Eyebrows): 轮廓点。
        *   颧骨 (Cheekbones): 上方关键点。
        *   额头 (Forehead): 眉心或额头中心点。
        *   鼻梁 (Nose Bridge): 上方点。
    *   **头部姿态:** 确认插件是否提供面部变换矩阵或精确的 3D 欧拉角。如果只提供欧拉角，算法需要基于此进行适配。

## 3. 实施步骤 (Flutter - Android 优先)

### 3.1 插件集成与配置

*   **添加依赖:** 在 `pubspec.yaml` 中添加 `google_mlkit_face_mesh_detection` 插件。
*   **原生配置 (Android):** 根据插件文档完成 Android 平台的必要配置（如 `build.gradle` 文件修改、权限声明等）。
*   **实例化与加载:** 创建 `FaceMeshDetector` 实例，并根据需要配置 `FaceMeshDetectorOptions`（如使用静态图片模式或流模式）。加载模型。

### 3.2 输入处理

*   使用 `camera` 插件获取 `CameraImage`。
*   正确转换为 `InputImage` 并传递给 `FaceMeshDetector`。

### 3.3 输出解析 (`FaceMeshDetectionService` - 需要创建或修改)

*   从检测结果 (`List<FaceMesh>`) 中提取：
    *   所有 468 个 3D 特征点 (`FaceMeshPoint`)。每个点包含 3D 坐标 (`position`) 和索引 (`index`)。
    *   确认是否有直接可用的头部姿态信息（欧拉角或矩阵）。
*   根据预定义的索引，筛选出我们需要的**关键区域特征点子集**进行后续处理。

### 3.4 注视方向判断算法 (核心逻辑 - 基于 468 点)

*   **输入:** 关键区域 3D 特征点子集、可能的头部姿态信息、设备物理参数（摄像头-屏幕偏移）。
*   **核心思路 (调整后):**
    1.  **(如果可用) 利用头部姿态:** 如果插件提供精确姿态信息（矩阵或可靠欧拉角），用其将关键点转换到统一坐标系。
    2.  **计算视线向量 (基于 Mesh):** 基于变换后的**虹膜区域/眼部轮廓点**估算眼球中心和瞳孔方向，计算 3D 视线向量。这需要详细研究 468 点的拓扑结构。
    3.  **目标区域判断:** 判断视线向量是否指向预定义的屏幕区域（考虑摄像头偏移）。
    4.  **利用稳定点:** 使用额头、眉毛、颧骨等稳定点辅助验证姿态或作为直接参考。
    5.  **设计容错:** 算法应能在部分非核心关键点丢失时仍能工作。
    6.  **输出置信度:** 根据可用关键点质量和姿态稳定性评估结果可信度。

### 3.5 调试与可视化 (`FaceMeshPainter` - 需要创建或修改)

*   绘制所有 468 个特征点（或至少是关键区域的点）。
*   **高亮显示算法使用的关键区域子集**。
*   可视化头部姿态（如果可用）。
*   显示计算出的视线方向（可选）。
*   显示最终判断结果和置信度。

## 4. 鲁棒性关键

*   算法设计**不强依赖**面部下半部分（嘴唇、下巴）的特征点。
*   优先利用（如果可用且可靠的）**头部姿态**信息进行坐标对齐。
*   利用额头、眉毛、颧骨等相对稳定区域的点进行**姿态验证或辅助判断**。
*   算法具备一定的**关键点缺失容忍度**。

## 5. 测试策略与平台限制

*   **主要测试平台:** Android。将使用用户提供的华为手机进行测试。
*   **GMS 依赖:** 需在测试中确认 `google_mlkit_face_mesh_detection` 在无 Google 移动服务 (GMS) 的华为设备上的兼容性和表现。
*   **iOS 平台:** 目前版本**无法**在 iOS 上运行核心的 Face Mesh 检测功能。后续需关注插件更新或考虑自行实现原生集成 (Platform Channels)。

## 6. 下一步行动

1.  **集成插件:** 将 `google_mlkit_face_mesh_detection` 添加到 `pubspec.yaml` 并完成 Android 配置。
2.  **实现 Service:** 创建或修改 `FaceMeshDetectionService` 以使用新插件的 API 处理输入和输出。
3.  **实现 Painter:** 创建或修改 `FaceMeshPainter` 以可视化 468 点网格。
4.  **初步算法:** 基于获取到的 468 点，实现第一版注视方向判断逻辑（优先 Android）。
5.  **设备测试:** 在华为手机上测试插件兼容性和算法效果。
