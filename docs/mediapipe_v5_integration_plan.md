# MediaPipe面部特征点检测 V5 实施规划

## 项目背景

开发一个面向动作受限患者的多设备交互系统，根据患者眼球和头部朝向判断意图。此版本将从Flutter跨平台方案调整为原生平台实现，以充分利用MediaPipe的全部功能，特别是虹膜检测和眼球运动方向识别。

## 技术选型

根据[MediaPipe官方文档](https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker?hl=zh-cn)的建议，采用以下技术实现方案：

### 客户端应用

1. **Android实现**：直接使用官方MediaPipe Face Landmarker API
2. **iOS实现**：直接使用官方MediaPipe Face Landmarker API
3. **协调器应用**：保留Flutter实现（可兼容移动/桌面平台）

### 关键功能与依赖

1. **3D面部网格**：478个关键点
2. **虹膜检测**：每只眼睛5个关键点（中心+4边缘点）
3. **眼球运动方向识别**：支持eyeLookLeft/Right/Up/Down等多方向检测
4. **面部转换矩阵**：提供准确的3D空间定位
5. **融合变形系数**：提供面部表情识别（可选功能）

## 系统架构

### 1. 视觉处理组件

- **平台**：独立的Android和iOS原生应用
- **功能**：
  - 摄像头参数控制与锁定
  - MediaPipe Face Landmarker初始化与运行
  - 虹膜和眼球方向实时检测
  - 提取关键特征并进行本地分析
  - 通过本地网络发送状态信号

### 2. 协调器组件

- **平台**：Flutter应用（可在移动设备或PC上运行）
- **功能**：
  - 接收多台设备的状态信号
  - 解释组合信号并执行状态机逻辑
  - 实现各种交互模式（简单选择、序列输入等）
  - 向客户端设备发送UI更新命令

### 3. 通信层

- **协议**：MQTT（首选）
- **模式**：本地网络模式，不依赖互联网
- **数据格式**：简化的状态信号（设备ID、状态、时间戳、置信度）

## 网络通信架构

系统采用混合网络架构，既保证核心功能在无互联网环境下可用，又支持互联网扩展功能。

### 1. 双层网络模式

#### 核心层：本地Wi-Fi Direct/P2P网络
- 用于设备间实时通信和核心功能
- 完全独立于医院网络基础设施
- 不依赖互联网连接
- 保证低延迟和高可靠性
- 保护隐私数据（如摄像头图像）仅在本地传输

#### 扩展层：互联网连接（可选）
- 提供非核心但有价值的扩展功能
- 互联网可用时自动启用
- 互联网不可用时优雅降级到纯本地模式
- 清晰区分需要互联网的功能和纯本地功能

### 2. 互联网扩展功能

#### 2.1 患者交流记录
- 本地存储最近的交流历史
- 互联网可用时自动同步到云端
- 支持按患者ID、日期等条件检索历史记录
- 数据加密传输和存储

#### 2.2 用户账号与设置同步
- 本地模式下使用设备ID作为临时身份标识
- 互联网可用时允许医护人员登录账号
- 同步用户配置、设备设置和患者信息
- 支持多设备间配置共享

#### 2.3 软件在线更新
- 检测新版本并提供更新
- 支持核心功能包和模型的独立更新
- 更新过程不影响系统正常使用
- 提供更新日志和回滚机制

#### 2.4 外部应用集成
- 与微信、医院系统等第三方平台集成
- 支持将交流结果分享到其他应用
- API接口支持更广泛的生态系统集成

### 4. 网络切换与状态管理

#### 4.1 自动网络探测
- 启动时检测可用网络
- 定期监控网络状态变化
- 显示当前连接模式指示器
- 提供手动切换选项

#### 4.2 优雅降级机制
- 互联网断开时自动切换到纯本地模式
- 不影响核心通信和视线检测功能
- 重连后自动恢复扩展功能
- 用户可见的状态提示

#### 4.3 数据同步策略
- 本地优先的数据存储
- 后台异步同步到云端
- 断点续传和冲突解决机制
- 电量和网络感知同步（避免在低电量或弱网络时同步）

### 5. 安全与隐私保护

#### 5.1 数据分级
- 敏感数据（如原始摄像头图像）仅在本地处理，永不上传
- 中度敏感数据（如视线方向信号）可在本地网络传输
- 非敏感数据（如匿名使用统计）可选择性上传到云端

#### 5.2 传输加密
- 本地通信采用TLS/DTLS加密
- 互联网通信使用HTTPS和WebSocket安全连接
- 端到端加密敏感数据

## 开发重点与挑战

1. **虹膜检测精度**：确保在不同光线条件下的准确性
2. **眼球方向判断**：需要区分微小的眼球运动和头部运动
3. **老旧设备性能**：优化以确保在目标华为和iPhone设备上流畅运行
4. **摄像头参数锁定**：确保摄像头曝光、对焦等参数的稳定性
5. **多设备同步**：处理不同设备间的信号时间同步问题
6. **无GMS环境**：确保在华为设备上正常运行

## 核心算法思路

### 视线方向判断

```pseudocode
function 判断视线方向(面部网格点[], 虹膜点[], 设备位置参数):
    # 1. 提取眼球中心和虹膜中心
    左眼中心 = 计算中心点(左眼网格点)
    右眼中心 = 计算中心点(右眼网格点)
    左虹膜中心 = 左眼虹膜点[0]  # 中心点
    右虹膜中心 = 右眼虹膜点[0]  # 中心点
    
    # 2. 计算虹膜偏移向量
    左眼偏移向量 = 左虹膜中心 - 左眼中心
    右眼偏移向量 = 右虹膜中心 - 右眼中心
    
    # 3. 结合MediaPipe提供的eyeLook参数
    左眼水平方向 = eyeLookOutLeft - eyeLookInLeft
    右眼水平方向 = eyeLookOutRight - eyeLookInRight
    垂直方向 = (eyeLookUpLeft + eyeLookUpRight) - (eyeLookDownLeft + eyeLookDownRight)
    
    # 4. 融合头部姿态和眼球方向
    头部姿态 = 从面部网格计算头部欧拉角()
    视线方向 = 加权融合(头部姿态, [左眼偏移向量, 右眼偏移向量, 水平方向, 垂直方向])
    
    # 5. 判断是否看向当前设备
    相对视角 = 计算视线方向与设备方向夹角(视线方向, 设备位置参数)
    置信度 = 计算置信度(相对视角, 虹膜点质量)
    
    return 是否看向设备, 置信度
```

## 配置参数

为适应不同用户和环境，系统将支持以下可配置参数：

1. **视线判断阈值**：判定为"看向设备"的视角阈值
2. **信号持续时间**：需要维持视线多长时间才触发信号
3. **头部/眼球权重**：头部姿态与眼球方向在判断中的相对权重
4. **虹膜检测置信度阈值**：过滤低质量的虹膜检测结果
5. **设备角色**：在交互模式中的设备功能设置
